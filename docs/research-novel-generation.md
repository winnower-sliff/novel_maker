## 二、生成管线：分层与滚动

### 2.1 自上而下的分层扩写（雪花写作法）

AI_NovelGenerator 的设定链是教科书式的**雪花写作法（Snowflake Method）**十步分层，每层一个小请求，前层输出作为后层输入：

```
核心种子（一句话公式）
  → 角色动力学（3-6人，驱动力三角+角色弧线+关系冲突网）
    → 世界构建（物理/社会/隐喻三维，每维≥3个可互动的动态元素）
      → 情节架构（三幕式：触发/对抗/解决，每幕3个转折点+伏笔回收方案）
        → 章节蓝图（每章元数据化，见 §3.1）
          → 章节草稿 → 定稿（更新摘要/状态/向量库）
```

关键经验：
- **核心种子有公式**：`当[主角]遭遇[核心事件]，必须[关键行动]，否则[灾难后果]；与此同时，[隐藏的更大危机]正在发酵`（25-100 字，显性冲突+潜在危机双层）。
- **角色不是档案卡而是动力学**：每个角色要"表面追求（物质）/深层渴望（情感）/灵魂需求（哲学）"三层驱动力 + `初始状态→触发事件→认知失调→蜕变节点→最终状态`弧线 + 至少两个价值观冲突 + 一个合作纽带 + 一个隐藏背叛可能性。
- **世界观三维交织**：物理（空间×阶层分布、历史年表、法则漏洞点）/社会（权力断层线、可打破的禁忌及后果、经济命脉）/隐喻（贯穿全书的视觉符号系统、环境映射心理）。要求每个维度包含**可与角色决策互动的动态元素**，而不是静态百科。
- Long-Novel-GPT 的变体：**创作章节（50章×200字）→ 创作剧情（每章扩到1k）→ 创作正文（1k扩到2k）**，三阶段均可 50 线程并行，靠多轮小扩写绕开单次输出长度限制，百万字级可行。

### 2.2 滚动规划（长篇不一次性出全纲）

ainovel-cli 的「指南针+视野滚动规划」是对"一次性生成 300 章大纲必然空洞"的回答：

- 初始只规划：**终局方向（指南针）+ 前 2 卷弧骨架 + 第 1 弧详细章节**；
- 弧结束时：Editor 生成弧摘要+角色快照 → Architect 参考前文摘要展开下一弧详细章节；
- 卷结束时：Editor 卷级评审 → Architect 创建下一卷并**更新指南针**（故事方向允许随创作演化）；
- 骨架弧只有 goal+预估章数，到达时再展开；
- 内置**通用节奏模板**：成长突破弧/竞技对抗弧/探索发现弧/恩怨冲突弧/日常过渡弧，每种弧型有参考密度和题材映射。

Novel-Claude 同思路：世界构建分五步（金手指→一句话梗概→故事大纲→世界设定→核心蓝图），先全书分卷大纲、写到某卷再生成该卷细纲。

### 2.3 上下文管理：三级摘要 + 相关章节推荐

500+ 章的上下文方案（ainovel-cli）：

```
卷（Volume）→ 卷摘要
└── 弧（Arc）→ 弧摘要 + 角色快照 + 风格规则
    └── 章（Chapter）→ 章摘要（滑窗最近3章）
```

- 近处用章摘要、中距离弧摘要、远处卷摘要，层层压缩；
- **相关章节智能推荐**：每章写作前从「伏笔、角色出场、状态变化、关系」四个维度反查历史章节，推荐 Writer 按需回读原文（不是把原文塞进上下文，而是给"哪几章值得读"的指针）；
- **下一章预告**：加载下一章大纲，帮 Writer 设计章末钩子和伏笔衔接；
- 上下文超窗时的**四级压缩管线**（代价从低到高）：`清理旧工具结果 → 截断长文本 → 用 store 已有摘要零 LLM 压缩替换旧消息 → LLM 摘要兜底`；LLM 摘要 prompt 明确保留"角色状态、伏笔线索、审稿待修项、风格锚点"；压缩后自动注入**恢复包**（当前章节计划+大纲+角色快照）防失忆；
- CJK token 估算用 `字数 × 1.5` 而非 `bytes/4`，避免低估导致压缩触发滞后。

AI_NovelGenerator 用另一条路：Chroma 向量库，每章定稿后入库；写作前用 LLM 先**生成检索关键词**（`[实体]+[属性]`、`[事件]+[后果]`、`[地点]+[特征]` 三类组合），再向量检索 top-k，再对检索结果做一次 **LLM 二次过滤**（见 §3.4）。

RecurrentGPT 的学术方案是"语言化 LSTM"：每步生成正文的同时生成**下一段计划**（短期记忆，语言化）+ 把本段摘要追加进长期记忆库（可检索）。即：生成请求的输出永远包含"正文 + 下一步计划 + 记忆更新"三件套。

## 三、Prompt 工程：章节级生成质量

### 3.1 章节蓝图元数据（让"写什么"结构化）

AI_NovelGenerator 的目录不是标题列表，而是**每章一份元数据卡**：

```
第n章 - [标题]
本章定位：[角色/事件/主题]        ← 章节类型
核心作用：[推进/转折/揭示]        ← 功能
悬念密度：[紧凑/渐进/爆发]        ← 节奏
伏笔操作：埋设(A线索)→强化(B矛盾) →回收(C伏笔)  ← 伏笔生命周期
认知颠覆：★☆☆☆☆（1-5级）        ← 转折强度
本章简述：[一句话]
```

生成正文时这些元数据**与摘要、前章结尾段、角色状态一起注入**，且同时注入**下一章元数据**（预告）。章节集群规则：每 3-5 章一个悬念单元，单元间设"认知过山车"（连续 2 章紧张→1 章缓冲）。

### 3.2 场景类型模板（正文内部的多样性强制）

AI_NovelGenerator 的正文 prompt 要求每章至少包含 2 个以上"具有动态张力的场景"，并给出四类场景的设计清单：

- **对话场景**：潜台词冲突（表面谈 A 实际博弈 B）；权力关系变化（非对称对话长度体现）；
- **动作场景**：≥3 个感官细节；节奏控制（短句加速+比喻减速）；动作揭示人物隐藏特质；
- **心理场景**：认知失调的具体行为表现；隐喻连接世界观符号；决策前的价值天平；
- **环境场景**：空间透视变化（宏观→微观→异常焦点）；非常规感官组合；动态环境映射心理。

这直接解决 AI 生成"全是平铺对话+总结式叙述"的问题——**把"要有好场景"翻译成可检查的硬指标**。

### 3.3 风格模仿：作者语料注入

Long-Novel-GPT 的「天蚕土豆风格」prompt 极简但有效——不做抽象风格描述，直接给**词汇级 few-shot**：

- 常用反派话语 5 句（"此子断不可留，否则日后必成大患！"…）
- 常用词语表（"旋即、苦笑、美眸、桀桀、负手而立、摧枯拉朽、虎躯一震…"）

经验：**风格 = 可复用的词句清单**，比"语言生动、有画面感"这类元指令可控得多。可以做成"风格库"（作者风格→语料表），生成正文时按需注入。

### 3.4 知识库三级过滤（RAG 结果的深加工）

AI_NovelGenerator 对检索回来的材料不直接塞 prompt，而是先过一道 LLM 过滤：

1. **冲突检测**：删除与前文摘要重复度>40% 的内容；标记世界观矛盾（▲前缀）；
2. **价值评估**：关键价值（❗：新角色关系可能性/可转化隐喻/≥2 个可延伸细节锚点）与次级价值（·：环境细节/技术描述）分级；
3. **结构重组**：按"情节燃料/人物维度/世界碎片/叙事技法"分类，每类附适用场景提示（如"可用于时间压力类悬念"）。

并在正文 prompt 里给**知识应用规则**：禁止复制已有情节模式；历史章节仅允许参照叙事节奏（相似度<20%）；相似度 20-40% 须替换至少 3 个关键要素；>40% 必须重构叙事角度。

### 3.5 中文写作技法知识库（chinese-novelist-skill 的核心资产）

这是目前见过最完整的**面向 LLM 的中文写作规则库**，全部是"规则+反例+正例+操作要点"格式，可直接抄进 system prompt 或 skill：

**开头十式**：行动中开场（in media res）/反常情境/震撼对话/倒计时/重大发现/危机时刻/谜团/背叛/重大选择/结局预告（倒叙）。每种配 5 个题材的示例。开头六忌：天气描写、日常流程、回顾上章、缓慢铺垫、平淡对话、过度解释。

**结尾钩子十三式**：突然揭示/紧急危机/未完成动作/身份反转/两难选择/神秘物品/时间限制/承诺威胁/离奇消失/言外之意/意象钩子（前文铺垫的意象结尾时变化）/回声钩子（首句呼应反转）/留白钩子（只写反应不写事件）。配五忌：虚假悬念（脚步声结果是猫）、机械降神、过度留白、低风险钩子（晚饭吃什么）、同质悬念（每章都用脚步声结尾）。

**章首引子七式**：悬念对话/闪前碎片/倒计时/神秘独白/反差场景/未完成动作/意象伏笔（50-150 字短引子）。

**悬念弧线编排**：
- 单章三段式：播种（前 20% 埋看似无关细节）→生长（中段偶尔冒头）→收获（结尾 10% 开花结果成钩子）；
- 三弧并行：短弧（2-3 章，即时满足）/中弧（5-8 章，情节波峰）/长弧（全书，核心谜题）**必须同时运行**；一条弧结束时至少另一条正在高潮；
- 悬念强度 1-5 级波浪式递进，二十章的小说通常 2-3 个高强度锚点；
- 每章至少回应一个旧悬念 + 提出一个新悬念；
- 「读者翻开下一章的理由，永远要在这一章的结尾给够——同时让读者惦记至少两件事」。

**打破预期四技术**：预期反转（铺垫 A 转 B，线索要能回看）、信息差利用（读者已知角色未知→焦虑；2-3 章内必须揭示）、复杂动机（反派立场揭示后读者不知站谁）、节外生枝（解决后 1-2 段内引入更大新变量）。

**中文文学技法**（可操作版）：白描（删掉形容词意思不变就删）、留白（高潮处戛然而止，写动作不写感受）、意象营造（一本书≤3 个意象，前期出现→中期变化→关键时刻爆发）、草蛇灰线（伏笔伪装成闲笔，间隔≥5 章，**伏笔必须登记台账**）、蒙太奇（场景直接跳切，A+B=C 在读者脑中完成）。

**节奏控制**：长短句交替（动作段≤10 字，连续三句同长必打破；转折处用极短句"他愣住了"）；段落呼吸（紧张一段一两句，缓和五六句，长段中插单句段如鼓点）；信息密度波浪（高密度后必跟低密度消化段，每章 2-3 个波浪）；全章节奏检查法（标每段速度画曲线，直线必改）。

**展示而非讲述对照表**：他很愤怒→他握紧拳头，指节发白；她很伤心→她低头搅咖啡，勺子停了很久。

**去 AI 味清单**：高频 AI 词出现一个改一个（"此外/然而/值得注意的是/彰显/诠释/映射/折射/不禁/油然而生/这一刻/仿佛/宛如"）；连续两个四字成语即堆砌；禁无意义"不是xxx"句式（"一声巨响撞进耳膜，不是雷声"→删掉后半句）；一句话"的"≤2 个；删模糊词（一些/某种/大概/似乎）；动词优于形容词。

**评分卡**：8 维度各 10 分——开头吸引力/情节推进/人物塑造/对话质量/悬念设置/节奏控制/展示而非讲述/语言质量，>60 可交付、>70 优秀，单项<6 必须改。

### 3.6 扩写技巧（防注水的扩写）

chinese-novelist-skill 的内容扩充指南，核心是**先诊断再扩**：

| 技巧 | 用法 |
|---|---|
| 场景肌理充实 | 五感细节、空间层次、时间流动感（按悬疑/言情/奇幻分策略） |
| 关键时刻放慢 | 打斗/告白/发现真相等高潮点反而减速，逐拍描写 |
| 内心世界展开 | 患得患失的完整心理过程（4 种展开手法） |
| 对话层次丰富 | 表层信息+潜台词+权力关系+情感暗流四层 |
| 次要情节穿插 | 配角片段/暗线推进/伏笔埋设/关系微变（四种穿插方式） |
| 感官维度叠加 | 同一场景叠加视觉外的感官（听觉/嗅觉/触觉/温度） |

防注水原则：扩写必须服务于人物/冲突/氛围之一，纯凑字的风景描写是毒药。NovelForge 的字数控制双模式也值得借鉴：`提示词约束`（自然便宜）vs `控制模式`（按目标总字数切分多轮预算，稳但贵）。

## 四、长篇一致性：状态与台账

### 4.1 角色状态文档（每章定稿后增量更新）

AI_NovelGenerator 的角色状态是**树状活文档**，章节定稿时 LLM 在原文档上增删（不改结构）：

```
张三：
├──物品: 青衫(破损带血渍)、寒铁长剑(断裂刻符文)
├──能力: 精神感知、无形攻击
├──状态: 身体状态 / 心理状态
├──主要角色间关系网: 李四:…、王二:…
└──触发或加深的事件: 村庄不明符号、李四被刺
新出场角色: …（淡出角色可删除）
```

更新规则写进 prompt：直接在已有文档上增删、不改结构、语言简洁。这比每章重新生成状态稳定得多。NovelForge 把同类能力泛化为六种实体（角色/关系/场景/组织/物品/概念）的轻量状态提取，统一「基于章节正文提取→预览→用户确认→写回卡片或图谱」流程。

### 4.2 设定词典（新名词首现管理）

规则（chinese-novelist-skill）：设定类名词首次出现时，读者必须当场知道它的**类别和一个可感知特征**，三选一：
- 类别+特征："一枚蓝晶，指甲盖大小，黑市上比金子还抢手"；
- 角色反应传递重要性：旁人看到倒吸一口凉气；
- 借对话点出门道："别声张，这东西在黑市能换条命"。

并维护设定词典：每个名词登记**首现章节/读者已知/完整真相/计划揭示章节**。写新章前核对：首现的须带线索；已介绍的表述不得超出「读者已知」栏；到达计划揭示章节的必须兑现。——这本质上是**读者视角的信息状态机**，比"世界观一致"更精细：同一设定，作者知道≠角色知道≠读者知道。

### 4.3 写前三步与穿针引线

写新章前的硬性三步（不可跳过）：①读全部已完成章节摘要；②读上一章原文结尾，找回语气和当前悬念落点；③核对人物状态（位置/情绪/关系/已知信息）。ainovel-cli 的 Writer 把它固化成工具调用顺序：`加载上下文→回读前章→构思本章→写→一致性检查→提交`（顺序严格，内容自主）。

### 4.4 一致性自动校验

- AI_NovelGenerator：独立的一致性检查器扫最新章节，查人物逻辑/情节矛盾，冲突写日志；
- chinese-novelist-skill：完稿后自动校验字数+连贯性，不合格**自动重写最多 3 轮**；
- ainovel-cli：`check_consistency` 作为 Writer 的必经工具步骤，对照状态数据检查后才允许 commit。

## 五、质量控制：评审与重写循环

### 5.1 七维评审（ainovel-cli Editor）

Editor 从七个维度审阅，**每项必须引用原文举证**：
1. 设定一致性；2. 角色行为；3. 节奏；4. 叙事连贯；5. 伏笔；6. 钩子；7. 审美品质。
   - 审美维度再细分五项：描写质感/叙事手法/对话区分度/用词质量/情感打动力。

评审结果驱动 Flow 状态机：`reviewing → rewriting（必须重写）/ polishing（只需打磨）/ writing`。这把"改稿"从模糊动作变成**结构化裁决**。

### 5.2 生成后处理管线

多个项目的正文产出流程都是多 pass 的：

```
草稿 → 润色（去AI味、语言质量） → 字数检查（不足则定向扩写/超长则删减） → 一致性检查 → 定稿（更新摘要/状态/伏笔台账/向量库）
```

字数不足的扩写 prompt（AI_NovelGenerator）：「以下章节文本较短，在保持剧情连贯的前提下扩写至 {N} 字左右，仅给出最终文本」。chinese-novelist-skill 则按 §3.6 的诊断式扩写而不是盲目"写长点"。

### 5.3 用户干预与影响面评估

- ainovel-cli：写作过程中随时注入修改意见（无需暂停），系统**自动评估影响范围并重写受影响章节**（steering Flow）；可选逐章验收模式；
- NovelForge：灵感助手（Agent）一次返回多条正文修改建议，编辑器逐条接受/拒绝；
- NovelClaw：可检视运行（progress.log、run 详情页），把黑盒生成变成可观察工作台。

## 七、对本项目（novel_maker）的落地建议

按投入产出比排序，结合现有架构（worldbuild 两步检索、pipeline.ts prompt 构建、agent 20 工具、graph.ts 全项目图谱、人物/世界观卡+tags）：

### P0（直接增强生成质量，改动小）

1. **章节蓝图元数据**：大纲生成升级为每章元数据卡（定位/核心作用/悬念密度/伏笔操作/认知颠覆星级/一句话简述），写正文时注入本章+下一章元数据（预告→章末钩子设计）。对应 §3.1。
2. **场景模板硬指标**：正文 prompt 加入"至少 2 类动态张力场景"+四类场景设计清单（对话潜台词/动作感官+节奏/心理认知失调/环境透视变化）。对应 §3.2。
3. **去 AI 味规则**：把 §3.5 的清单（高频词黑名单、"不是xxx"句式、"的"字密度、展示而非讲述对照表）写进润色/改写 prompt 与内置 skill。
4. **风格语料库**：仿天蚕土豆 prompt 的做法，建"风格卡"（作者/流派→常用词句表），正文生成时可选注入。可作为新的内置 skill。

### P1（长篇一致性，需要新数据结构）

5. **角色状态活文档**：人物卡增加"动态状态"区块（物品/能力/身心状态/关系/触发事件），每章定稿后 LLM 增量更新（prompt 范式照抄 §4.1：在原文档上增删、不改结构）。生成正文时注入出场角色的当前状态。
6. **伏笔/悬念台账**：新板块（或大纲的附属结构）：每条记录`埋设章→强化章→计划回收章→状态`；写作时注入"本章应埋/应收"的条目；结合 §3.5 三弧并行原则在大纲层校验悬念密度曲线。项目已有伏笔板块雏形的话，重点补"生命周期"字段。
7. **设定词典**：世界观条目增加"读者已知/完整真相/计划揭示章"字段（世界观卡已有 type/tags 体系，加字段成本低），生成时防剧透：已介绍条目的表述不得超出「读者已知」。对应 §4.2。
8. **分层摘要**：卷/弧/章三级摘要，写正文时按距离注入；配合已有的两步检索（小请求检索→只注入相关正文），把"相关章节推荐"（伏笔/出场角色/状态变化/关系四维反查——可复用 graph.ts 的边数据）作为指针给 agent/写作管线。

### P2（质量闭环，生成后多 pass）

9. **评审 pass**：七维评审（每维引用原文举证）→ 产出"重写/打磨"结构化裁决 → 自动重写循环（≤3 轮）；可做成 pipeline 的新阶段或 agent 工具（`review_chapter`）。
10. **字数控制双模式**：提示词约束（默认）+ 控制模式（多轮预算切分，目标字数大的章节用）。
11. **诊断式扩写**：不足字数时不盲目"写长点"，按 §3.6 六技巧先诊断（缺场景肌理？缺心理？缺对话层次？）再定向扩。

### P3（工程化）

12. **写前固定序列**：agent 写章时固化工具顺序（加载上下文→回读上一章结尾→查状态→写→一致性检查→提交），顺序严格内容自主。现有 agent 工具已具备大部分能力，缺"回读上一章结尾"与"一致性检查"两个工具。
13. **断点恢复**：长篇批量生成任务的 step 级 checkpoint（哪一章哪个 pass 完成），崩溃续跑。
14. **模型路由**：大纲/蓝图/校验走 Flash 级（便宜），正文走 Pro 级——现有 provider 多配置已支持，只差任务级路由选择。

# 第二轮调研（2026-09）：RAG 原理对比与进阶工程经验

> 本轮目标：①弄清 RAG 原理及其与现有方案的关系；②补挖一批未覆盖的项目。结论已落地为 v5 实施计划（模块 A-H）。

## 一、RAG 原理与现有方案对比

### 原理三步

```
①切块：资料切成小段（chunk）
②向量化：embedding 模型把文字映射为"语义坐标"（向量，意思相近则坐标相近）
③检索注入：查询向量找最近邻的 k 段，塞进上下文
```

### 与现有方案的关系（重要）

RAG 不是"更先进的替代品"，而是检索的一种实现方式。本项目已具备**混合检索**能力：

| 检索手段 | 标准向量 RAG | 本项目现状（v4） |
|---|---|---|
| 语义检索 | 核心 | 本地 bge-small-zh（零 token） |
| 关键词/结构检索 | 通常缺失 | 更强：`[[链接]]`图谱1跳 + 标题/别名命中 + type/tag 过滤 |
| LLM 判断检索 | 无 | worldbuild 两步生成检索小请求 |
| 分层注入 | 无 | 最近5章摘要 / 卷摘要 / 全量·子图·标题清单三级降级 |

小说场景的设定库是**强结构**，优于 RAG 面向的"海量弱结构文档"前提。RAG 框架中值得借鉴的两招已落地：**关键词路（条目别名 keys）+ 融合重排**（v5 模块 C）。
